# 轨迹 AI 图片创作：第二版 UI 布局

日期：2026-10-05  
状态：已确认并完成第二版实现。实现及验证见 [验证记录](track-ai-image-workspace-validation-v2.md)。

本稿替代第一版中的 AI 侧栏、美化/生图两个模式及文字任务列表。轨迹资源库仍保留为独立页面。

## 1. 对需求的理解

统一功能命名为 **AI 图片创作**，使用一个独立页面完成照片优化和图片生成。

- **主体参考图**可以多张，用来提供人物、景物、装备、构图等内容依据。
- **效果参考图**可以多张，用来提供色调、光影、质感、画风等效果依据。
- 任一组有图，都根据参考图和提示词创作；两组都为空时，直接根据提示词生成。
- 不再要求用户选择“AI 美化”或“生成图片”模式，主要操作统一为 **生成图片**。
- 资源库顶部原“生成图片”的位置改为 **历史记录**；AI 创作页顶部也提供同一历史入口。
- 历史按任务展示生成的结果图。点击结果缩略图，进入创作页并恢复当时的输入配置与结果。
- 恢复历史任务不会自动发起新生成。用户修改或继续使用配置后，点击“生成图片”才创建新任务。

资源库负责素材管理，AI 创作页负责输入和结果，历史页负责找回曾经的任务。

## 2. 页面入口

### 2.1 资源库

```text
┌───────────────────────────────────────────────────────────────────┐
│ ← 返回轨迹详情                                                     │
│ 轨迹资源库                         [历史记录] [视频制作] [刷新资源] │
│ 所属轨迹：当前路线                                                 │
├──────────────────────────────────────────────┬────────────────────┤
│ [全部] [图片] [视频] [音频]      [导入资源]    │ 资源详情           │
│ 搜索 / 筛选                                  │                    │
│                                              │ 当前选中素材       │
│ 图片、视频、音频网格                          │ 名称、标签、来源   │
│                                              │                    │
│                                              │ [AI 图片创作]      │
│                                              │ [添加到点位]       │
└──────────────────────────────────────────────┴────────────────────┘
```

入口行为：

| 入口 | 打开 AI 创作页后的初始状态 |
|---|---|
| 未选素材，点击“AI 图片创作” | 两组参考图为空，等待填写提示词或添加图片 |
| 选中一张图片后进入 | 该图进入主体参考组；仍可继续添加其他图片 |
| 多选图片，点击“用所选图片创作” | 所选图片进入主体参考组，可排序和重新分类 |
| 轨迹点位照片中的 AI 入口 | 将明确选中的照片加入主体参考组，保留所属轨迹 |
| 视频或音频被选中 | 可打开空白创作页，视频和音频不作为图片参考输入 |

资源详情只保留创作按钮，不在右侧继续展开完整的 AI 表单。新建创作页草稿时，两组参考图与提示词均从空白开始；已有草稿则保留，并由用户选择继续或新建。

## 3. 独立 AI 创作页

### 3.1 桌面布局

采用 **左侧结果预览 + 右侧创作配置**。预览区约占 2/3，配置区约占 1/3；配置区建议宽 360–440px，并随可用空间调整。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ← 返回资源库                                          [历史记录]    │
│ AI 图片创作 · 当前路线                              [新建创作]      │
├───────────────────────────────────────────────┬──────────────────────┤
│                                               │ 主体参考图 · 3 张    │
│                  结果预览                     │ [主体1] [主体2]      │
│                                               │ [主体3] [+ 添加]     │
│        首次进入：等待生成的图片区域            │ [从资源库选择]       │
│        完成之后：展示当前任务生成结果          │                      │
│                                               │ 效果参考图 · 2 张    │
│                                               │ [效果1] [效果2]      │
│                                               │ [+ 添加]             │
│                                               │ [从资源库选择]       │
│                                               │                      │
│                                               │ 提示词               │
│                                               │ [我的模板]           │
│                                               │ [参考 e图宝]         │
│                                               │ ┌──────────────────┐ │
│                                               │ │ 描述画面和修改要求│ │
│                                               │ │ 说明多张图的关系  │ │
│                                               │ └──────────────────┘ │
│                                               │ [保存为模板]         │
│                                               │                      │
│ [结果1] [结果2] …                             │ 模型 [已选模型   ▾]  │
│ 当前结果：1 / 2                               │ [生成设置 ▾]         │
│                                               │                      │
├───────────────────────────────────────────────┤ 主体3张 · 效果2张    │
│ [保存到资源库] [添加到点位] [用于视频] [下载]   │ [    生成图片    ]   │
└───────────────────────────────────────────────┴──────────────────────┘
```

说明：图中张数和生成结果数量仅为布局示意。实际输入上限与输出选项遵循所选模型和宿主能力。

### 3.2 主体参考区

- 可本地上传、拖入图片、从当前轨迹资源库多选。
- 每张图显示缩略图、编号、名称和移除操作。
- 第一张默认标记“主图”，用户可重新指定主图；其余图用于补充内容。此标记说明任务意图，不承诺模型严格保留其构图。
- 支持排序，也支持把误放的图片移动到效果参考组。拖动之外提供可点击的排序操作。
- 点击图片可放大查看。移除这里只改变创作输入，不删除资源库原文件。
- 用户可在提示词中写清关系，例如“以主体1的山景为基础，采用主体2中的背包”。这一句仅为说明示例，不作为默认预设填入。

### 3.3 效果参考区

- 上传和选择方式与主体参考一致，单独维护图片列表和编号。
- 区域说明为“参考色调、光影、质感或画风”。
- 不把效果图默认为需要出现在画面中的人物、景物或物品。
- 不设置没有实际模型能力支撑的“风格强度”等滑杆。
- 同一张图跨组重复加入时，提示用户选择主要用途，避免无意重复发送。

### 3.4 提示词与生成设置

提示词只有一个输入框，默认空白。用户可说明要生成的主体、如何使用参考图，以及希望调整的效果。

- “我的模板”初始仍为空，用户自己添加。
- “参考 e图宝”提供提示词案例；填入案例不自动加入案例图片。
- 不将用户模板与当前任务配置混为一体：模板保存文字，任务历史保存图片和完整配置。
- 模型选择放在提示词下方。画幅、质量、输出张数放入可展开的“生成设置”，仅显示已支持的选项。
- 主按钮始终叫“生成图片”。按钮旁显示实际输入摘要，而非另设模式开关。

| 主体参考 | 效果参考 | 页面的输入摘要 | 生成意图 |
|---|---|---|---|
| 无 | 无 | 根据提示词生成 | 由文字描述决定内容和效果 |
| 有 | 无 | 主体参考 N 张 | 依据主体图与文字要求优化或创作 |
| 有 | 有 | 主体 N 张 · 效果 M 张 | 内容依据主体图，视觉效果参考效果图 |
| 无 | 有 | 效果参考 M 张 | 提示词描述主体，参考效果图的视觉表现 |

多图模式只允许使用已确认支持多图的模型。超过模型上限时明确提示更换模型或调整图片，不能静默只发送第一张图。

### 3.5 左侧结果区

**生成前：**显示简洁空状态；可在主预览中检查主体主图，但标注“输入参考”，避免与结果混淆。

**生成中：**显示任务状态。提交时保存输入快照；之后即使用户改动右侧草稿，也不改变正在执行的任务。

**生成完成：**显示生成图片，下方缩略图切换同一任务的多个结果；选中哪张，下方保存、点位、视频和下载操作就针对哪张。

有主体参考时提供“结果 / 对比”操作。对比时可选择一张主体参考与结果并排显示；效果参考保持在右侧查看，不自动当作对比原图。没有主体参考时，主要展示生成结果。

预览历史结果时标注“历史任务结果”。如果右侧配置已被修改，提示“配置已修改，再次生成将创建新任务”，当前历史结果仍可浏览。

## 4. 历史记录页

### 4.1 图片任务网格

历史记录从资源库顶部原“生成图片”位置进入，也可从 AI 创作页进入。推荐使用完整页面，方便浏览较多图片。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ← 返回资源库 / 返回 AI 创作                                          │
│ 历史记录 · 当前路线                                                  │
├──────────────────────────────────────────────────────────────────────┤
│ 搜索提示词 / 任务名     [全部状态 ▾] [最新优先 ▾]                    │
├──────────────────────────────────────────────────────────────────────┤
│ ┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐          │
│ │                 │ │                 │ │                 │          │
│ │ 任务 A 的结果图 │ │ 任务 B 的结果图 │ │ 任务 C 的结果图 │          │
│ │             [⤢] │ │             [⤢] │ │             [⤢] │          │
│ ├─────────────────┤ ├─────────────────┤ ├─────────────────┤          │
│ │ 提示词摘要      │ │ 提示词摘要      │ │ 提示词摘要      │          │
│ │ 主体3 · 效果2   │ │ 无参考图        │ │ 效果1           │          │
│ │ 14:20 · 已完成  │ │ 昨天 · 已完成   │ │ 昨天 · 已完成   │          │
│ │ 2张结果         │ │ 1张结果         │ │ 1张结果         │          │
│ │ 点击恢复任务    │ │ 点击恢复任务    │ │ 点击恢复任务    │          │
│ └─────────────────┘ └─────────────────┘ └─────────────────┘          │
│                                                                      │
│ [任务 D：生成中…]                [任务 E：失败 · 可恢复要求]          │
└──────────────────────────────────────────────────────────────────────┘
```

卡片规则：

- 一张卡片对应一次任务，封面用该任务真实生成的结果图。
- 多结果显示数量，可在卡片内切换结果缩略图，避免每张输出看起来都是一条独立任务。
- **点击封面或“恢复任务”，打开创作页并恢复该任务。**卡片始终提示这个点击行为。
- 右上角放大按钮仅查看大图，不恢复或替换草稿；提供文字提示与键盘操作。
- 生成中、失败和已取消任务也保留，用状态卡片展示，不能伪装成成功结果图。
- 历史范围默认是当前轨迹；进入历史页和返回都保留资源库筛选或创作草稿。

### 4.2 “还原任务”的具体含义

恢复这些内容：

1. 主体参考图的完整列表、顺序和主图标记。
2. 效果参考图的完整列表和顺序。
3. 用户当时实际提交的完整提示词。
4. 当时的模型与已支持的生成设置。
5. 原任务生成的结果图，点击哪张则优先显示哪张。

恢复后，用户来到同一个独立创作页，可以修改、重新生成或直接使用历史结果。原任务保持完整，再次生成建立新任务，并保留“来自任务 A”的关系。

恢复时的特殊情况：

| 情况 | 处理 |
|---|---|
| 当前草稿没有修改 | 直接恢复并提示“已恢复历史任务，尚未提交生成” |
| 当前有修改过的草稿 | 提供“保留草稿并恢复 / 留在当前创作”；保留的草稿可以找回 |
| 某张参考图文件缺失 | 保留其编号和名称，显示缺失状态；补回或明确移除后再生成 |
| 原模型已不可用 | 保留原模型名称提示用户更换，不自动换模型提交 |
| 失败或已取消任务 | 恢复输入与设置，结果区显示原任务状态 |

恢复任务不修改轨迹照片，不恢复成旧的轨迹编辑状态，也不重复提交原任务。

## 5. 窄窗口布局

可用宽度不足以容纳两栏时，创作页改为同一页面中的“创作配置 / 生成结果”两个视图。它们只切换显示区域，不代表两种 AI 生成模式。

```text
┌──────────────────────────────┐
│ ← 返回          [历史记录]   │
│ AI 图片创作                  │
│ [创作配置] [生成结果]        │
├──────────────────────────────┤
│ 主体参考图                   │
│ [主体1] [主体2] [+ 添加]      │
│ 效果参考图                   │
│ [效果1] [+ 添加]             │
│ 提示词 / 模板                │
│ 模型 / 生成设置              │
├──────────────────────────────┤
│ 主体2 · 效果1                │
│ [        生成图片        ]    │
└──────────────────────────────┘
```

历史页用两列或单列结果卡片；图片与按钮均有明确可点击区域。生成完成后显示可操作的“查看结果”提示，避免切换视图导致输入丢失。

## 6. 本轮需要替换的现有 UI

| 当前 UI | 新设计 |
|---|---|
| 资源库右侧 AI 表单 | 独立 AI 图片创作页 |
| “AI 美化 / 生成图片”模式标签 | 一个统一入口与一个生成按钮 |
| 单参考图 | 主体参考组 + 效果参考组，均可多图 |
| 顶部“生成图片”按钮 | 同位置改为“历史记录” |
| 底部文字任务记录列表 | 以生成结果图展示的历史任务页 |
| “编辑要求”只恢复提示词和模型 | 点击历史图片恢复完整图片输入、设置和结果 |

资源库原有的上传、标签、预览、点位关联和视频用途功能继续保留。UI 颜色、字体、按钮、边框和深浅主题沿用 DSH 现有样式。

## 7. 实现边界说明

本次已核对本地 e图宝 宿主协议：`GenerationRequest` 已有 `image` 与 `images[]`，支持传递多参考图；协议同时说明部分服务只消费第一张参考图。因此新版需要核验实际模型能力，而不能仅依据界面已上传多张图就声称多图生效。

Track 当前创作适配和任务快照仍采用单张来源。落实本稿时，需要保存两组图片及其顺序、角色和完整生成配置，再接入宿主多图请求。宿主的图片数组没有“主体/效果”独立字段，两组意图需由任务配置与提示词组织明确表达。

本稿不把多参考图、效果图或新历史恢复行为标记为已实现，也未调用真实 AI。

设计参考：沿用现有 DSH 主题与交互习惯。UI 技能库未检索到适用的创作历史布局条目，页面层级和恢复规则依本次需求设计。
