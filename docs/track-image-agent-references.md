# 轨迹图片的 Agent 引用

已为资源库图片、已落盘的 AI 生成结果、精选模板参考图和带图的 e图宝模板案例增加两个入口。

- **复制图片引用**：准备图片副本，复制图片引用 ID、来源 ID、图片名称、真实本地路径和 `read_image` 读取指令。粘贴到 Agent 后，可补充“分析这张图”或“参考这张图调整提示词”。复制本身不会运行模型。
- **添加到 Agent**：打开或恢复当前轨迹项目的助手会话，把图片追加到原生对话草稿，保留已有文字和附件。用户手动发送后，支持图片输入的模型才能分析图片。

资源库和生成结果详情完整显示原有图片 ID，不使用省略号。模板引用和资源引用分别携带其来源，避免混淆不同来源的编号。

## 图片副本与读取

复制或添加时，只准备用户当前明确选择的图片。已保存轨迹的副本位于 `<DSH_HOME>/track-agent/tracks/<trackId>/image-references/`，图片和对应 JSON 记录成对保存。轨迹列表未选线路时，模板参考图使用公共目录 `<DSH_HOME>/track-agent/轨迹/image-references/`。引用 ID 按项目、来源和副本内容计算；同一项目、同一来源、同一内容的重复操作复用相同 ID；不同轨迹选择相同模板时分别保存。原图变化会得到新引用，已复制的引用仍指向当时的内容。

副本保留图片比例，应用原图方向，最长边不超过 2048 像素，优先 PNG；超过副本大小上限时转换为 WebP。不会裁切图片，也不会修改原文件、轨迹内容或用户已有的 `AGENTS.md`。

添加到 Agent 时，资源图片必须属于当前选择的轨迹；模板图片自动使用当前项目。切换轨迹会取消尚未完成的图片准备或添加，避免进入另一条线路的草稿。旧公共目录中的副本保留，原已复制的本地路径仍指向原文件；使用新入口时会在对应项目重新准备。

Agent 使用宿主已有的 `read_image({file_path: ...})` 读取工作区中的真实图片。当前模型必须支持图片输入，且 Agent 必须有图片读取工具；不能根据 ID、文件名或模板标题猜测图片内容。复制的是完整引用，不是伪造的宿主附件编号。

添加草稿使用官方 `sessions.scope(sessionId)`、`conversation.input.for(scope)`、`createDrafts` 和 `addAttachments`。不探测其他插件 DOM、不另建聊天界面、不调用发送接口。忙碌或失效的输入框拒绝添加时，只释放本次新建附件。

## 失败处理

剪贴板不可用时，显示可手动选择复制的完整引用。图片已移除、来源不匹配、服务不可用、读取超时、格式损坏或内容超过上限时，显示具体错误。模板弹窗只在成功添加到草稿后关闭；复制或添加失败时保留弹窗。

模板图片经现有 e图宝图片接口读取。精选使用随插件提供的来源与图片标识；普通参考案例先核对当前来源、案例编号和图片标识。后端仅访问实际宿主监听端口上的固定接口，不以请求 Host 头或用户 URL 作为下载地址。

验证记录与页面截图位于 `outputs/image-agent-reference-validation/`。浏览器验证中的 Agent 外壳为显式测试夹具；真实原生 Conversation 的验证结果单独记录。没有调用真实 AI、提交生成任务或修改安装 Profile。

## Desktop 模板参考图 403 修复（2026-10-05）

DSH Desktop 的原生网络会话自动向请求添加内部访问凭证。图片引用准备在 Node 后台调用 e图宝模板接口，原先没有继承这项凭证；普通浏览器访问关闭时，Desktop 在模板接口之前拒绝请求，返回 403，页面显示“宿主模板图片服务不可用”。运行中的 Beta 端口也确认了无凭证图片请求返回 `403 text/plain forbidden`。

现在从已通过宿主门禁的原始请求提取单一 `x-dsh-desktop-renderer` 能力头，校验格式后只向实际宿主端口的固定模板 GET/POST 接口转发。不会转发 Cookie、用户 Host 或其他请求头，不跟随重定向；凭证不会进入引用 JSON、图片路径、剪贴板或持久化记录。模板 HTTP 失败会附上状态码，方便区分后续错误。

- 相关回归测试 18 项通过，类型检查与插件构建通过。
- 独立验证使用 Beta 实际 `createDesktopBrowserAccess` / `decideDesktopBrowserAccess`、生产 Track 处理器、真实本地 HTTP 与图片解码。关闭普通浏览器访问时复现旧流程内层 403 / 外层 502；修复后精选、动态模板及本地图片资源均为 200。未准入请求仍为 403，重定向没有泄漏凭证。
- 独立验证的 e图宝图片和索引响应为测试夹具；没有读取当前桌面凭证、改动 Profile 或重启用户应用。当前 Desktop 会话需要重载轨迹插件后再点击验证。

证据：`outputs/image-agent-reference-validation/desktop-gate-regression.json`。本次仅修改两个图片引用后端文件、相关测试与本文档。

## 每条轨迹独立项目（2026-10-05）

已保存轨迹的原生 Agent 使用 `<DSH_HOME>/track-agent/tracks/<trackId>/`。会话绑定、上下文、项目说明和图片引用都属于该目录。相同轨迹再次进入会复用有效会话；不同轨迹使用不同项目和会话。目录由稳定编号决定，不随同编号线路的名称变化。

Agent 已展开时，切换线路会自动切到对应项目；返回原线路恢复其历史与未发送草稿。同一轨迹内切换详情、编辑、资源库、图片创作和历史页面只更新上下文。各项目的请求和上下文写入分别排队，旧请求的晚响应不能选中其他轨迹或向另一条轨迹追加图片。

轨迹列表和未保存的新路线仍使用原公共「轨迹」目录。旧公共目录、旧逐线路目录、文件和历史会话保留，不自动搬移或拆分旧对话；新轨迹项目从自己的会话开始。删除线路不会自动删除其 Agent 项目文件，应用会拒绝通过已删除线路重新打开项目。

验证涵盖目录/会话/context 隔离、A/B/A 复用、公共页面、新建路线、取消与晚响应、图片归属、旧数据保留，以及安装版原生 Workspace API 契约。最终相关 8 个测试文件共 117 项通过，类型检查与构建通过。Desktop 图片门禁回归再次通过，保持模板读取修复。原生宿主切选会话时可能释放上一条线路的输入 scope，因此轨迹面板现在通过官方 `sessions.retain` 持有访问过的项目。面板存活期间 A/B 的未发送文字和图片分别保留；面板卸载时统一释放项目引用。未发送图片不保证跨重启恢复。

独立原生测试使用实际 Beta `UiWorkspaceService`、`InputHub`、`SessionInputShell` 和 `ConversationController`，官方测试运行时提供 Session 传输与 scope。负对照确认缺少项目 holder 会销毁旧图片，实际 helper 正例确认 A/B/A 保持各自文字和图片、PNG 字节一致、重复 holder 去重和最终正确回收，发送/模型调用均为 0。证据：`outputs/per-track-agent-validation/native-project-draft.json`。
