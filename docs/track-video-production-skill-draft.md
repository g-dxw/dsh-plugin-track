# 轨迹视频制作 Skill 草稿

版本：v0.8

整理日期：2026-10-07

状态：综合讨论稿。结合武功山试跑沟通，整理口播、沿线叙事与画面制作方法；尚未创建、安装或启用正式 Skill。通用流程与具体项目选择分开记录，武功山当前选择见第六节。

## 一、目标与范围

把已整理的路线资料、用户真实素材，以及插件的地图、3D 地图、3D 沙盘、SVG 标注和资源图片/视频，组织为有明确观众收益的视频方案，并按用户要求推进到脚本、素材、片段或成片。

视频可以讲路线攻略、一次旅行故事、连续同行体验或风景吸引力；用户明确需要纯轨迹视频或某个地图片段时，也按其任务组织。影片由目标决定，不从现有地图能力、照片数量或某个镜头案例反推视频类型。

按当前任务进入相应阶段。已有明确采用的目标、大纲、脚本或镜头直接复用，不从头询问；只做脚本时交付脚本，需要制作时在已授权范围内继续执行。脚本设计、试镜、录制、配音和合成分别记录实际完成状态。

| [旅行视频脚本](skill-drafts/travel-video-script/SKILL.md) | 主目标、素材范围、叙事结构、大纲与脚本 | 作为内容策划参考，本稿连接后续镜头与制作流程 |
| Track 地图与镜头组件 | 二维地图、真实地形 3D 地图、3D 沙盘、镜头编排与片段导出 | 按表达任务选择视图，操作并记录可复用工程 |

信息整理不承担生图或成片制作；图片创作不决定影片叙事。本 Skill 负责把已采用的内容与素材组织成视频，并使每个画面有清楚的作用。

## 三、输入与状态

先提取已有对话和文件中的信息：

- 视频主目标、观众收益、素材范围和当前要交付的阶段。
- 最新路线资料、原始轨迹、当前点位与分组、确认后的地点和分段经历。
- 用户可用的照片、视频、现场声音、经历、笔记及其他明确选用的素材。
- 当前地图与沙盘设置、SVG 标注文档、资源库图片/视频及其资源 ID、来源点位、文件路径和用途。
- 已有大纲、脚本、提示词、镜头工程和候选样片，以及其中已采用的内容。
- 相关的平台、横竖屏、时长、讲述方式、风格及实际制作限制。

同一条内容分别记录三种状态：**事实是否核实、素材是否已取得或制作、内容是否已采用。** 网上文章可以支持事实，但其中的画面不自动成为可剪辑素材；候选样片已导出也不代表已采用。

采用记录写清场景编号、版本、确认对象、范围和用户依据，区分开场口播、画面方式、具体镜头、全片脚本与制作清单。用户选择某版口播或指定某段用沙盘，只确认该项；已确认内容直接沿用，修改后仅将受影响部分重新提交审阅。

资料使用最新确认版本。旧武功山模板只借鉴结构；过时的分段、点位数量、时间或费用，不覆盖现有资料中的用户确认结果。

## 四、执行流程

### 4.1 先确定视频主目标

新项目先检查用户希望观众主要获得什么。未说明时，先问主目标，不提前写大纲或替用户选类型：

| 主目标 | 观众收益 | 内容重点 |
| --- | --- | --- |
| 路线攻略 | 判断怎么走、怎么安排 | 路线特点、分段、实际投入、交通补给、下撤返程及适用条件 |
| 旅行故事 | 跟随真实经历、选择与变化 | 人物目标、真实过程、选择和结果 |
| 沉浸同行 | 感受连续旅程 | 空间推进、环境、身体体验、现场声与停顿 |
| 风景宣传 | 理解路线吸引力，愿意进一步了解 | 代表景观、体验期待及必要的地点和条件 |

用户可自行描述目标，也可在主目标明确后增加辅助目标。目的地或“电影感”不能代替观众收益；已有明确目标直接沿用。用户只要求试一个地图镜头时，以该镜头的表达任务为目标，不展开整片策划问卷。

### 4.2 确认素材范围与最小简报

目标确定后，再检查素材范围：只用当前已有素材，还是允许结合路线理解、外部资料和用户后续提供或补拍的素材。已有范围选择不重复询问；关键范围未定时先解决这一项，不能把用户未表态当成允许扩展。

提取一句创作命题：**给谁看，用哪些资料和画面，讲什么，观看后获得什么。** 平台、时长和风格缺失时可使用注明的暂定设置；只追问会改变主目标、核心结论或关键制作安排的内容。

用户提供实拍、现场声音与真实经历，Agent 负责结构、脚本、选材、插件操作和已授权的动画、录制及合成。素材不必全部到齐才开始策划；缺少画面时先检查已有图片、SVG 和地图能否完成表达，再说明仍需补充的真实素材。插件画面承担路线和信息解释，实拍与用户经历承担真实行程。用户明确要求纯轨迹视频时，轨迹可以承担主体。

### 4.3 复用路线资料，建立事实与素材清单

从已整理的资料提取本片需要的路线、统计、分段、重要节点、用户经历和实用信息，关联来源、点位编号及素材文件。只补齐与本次目标有关的缺口，不重复做全部路线调查。

点位和图片按表达需要选择性核对。先读取已有索引、分组概述和确认结果，挑选少量影响路线理解或视频表达的重要节点，如起终点、分段边界、代表景观、关键补给或下撤点；每个节点抽查少量代表图片，足以确认和选材后停止。普通点位和未选图片保留索引，不默认逐点、逐张全面检查。只有具体疑点或后续拟采用的画面需要核实时，才局部扩大范围，并记录原因。

完整攻略、旅行故事或风景内容还要筛选与主目标有关的背景，帮助观众理解目的地和画面。先复用信息整理稿中的调查结果，不足时由 Agent 有针对性补充：

| 背景层 | 挑选内容 | 放入视频的作用 |
| --- | --- | --- |
| 目的地位置 | 所在省份/行政区、地理区域、所属山脉或山域及代表特色；按目的地选择适用层级 | 开场钩子之后简短聚焦目的地，回答“这条线在哪里” |
| 徒步线路位置 | 线路在山域中的位置、入口/出口、相对重要山峰或景区的位置、节点顺序和行进方向；有依据时比较其他走法 | 从区域地图聚焦本次路线，让观众理解从哪进、沿哪走、从哪离开，以及各段如何衔接 |
| 自然与环境 | 地形、草甸/森林等景观、季节变化，以及确有依据且值得讲的地质或生态知识 | 放在相应景观段，解释看到什么、有什么特点，精华段可以展开 |
| 重要节点 | 地点的代表景观、沿线作用、可靠的名称或历史背景 | 随路线到达穿插，避免节点只有名称和服务价格 |
| 人文与户外活动 | 实际沿线的建筑、历史文化、聚落或当地户外活动 | 根据路线相关性与画面取舍，保留少量有助理解的内容 |
| 网络文化与流行说法 | 与目的地相关的网红梗、昵称、话题和传播现象；记录可查的表述与使用语境 | 作为开头或段落衔接的可选表达，增加亲近感，按用户风格与素材取舍 |

目的地位置可按“省份 → 地理区域 → 山脉/山域 → 本次线路”展开，区域层级与山脉归属使用地理资料，具体线路由真实轨迹与已确认点位定位。

网红梗记录原文/来源、传播语境、拟放段落、表达作用和候选状态，不必每段都使用。流行说法可作幽默或连接观众已有印象，不能据此推断路线难度、用户的出行动机和体感；不为套梗编造“出发豪言、途中崩溃”等过程。介绍一个已有说法与创作新的改写分别标明，未核实首创者或当下热度时不作相应断言。

线路位置介绍从当前真实轨迹、有效点位与确认后的路线名称提取。区分所在区域、相对方位和实际行进顺序；地图转向不改变地理方位，SVG 排版位置不作为定位依据。局部景区路段的收费或开放条件不推广到整条线路，正穿/反穿等叫法按具体路线与已核对资料说明。

每条背景记录内容、来源、对应路段/节点、介绍目的与可用画面。景观成因、地名来历和历史年代需要相应依据；传说标为传说。地图/DEM 能展示地形，不能独立证明生态成因；照片展示可见景观，不自动证明历史、季节规律或用户经历。资料已经核实但缺对应画面时，分别记录事实状态和制作安排。

区分用户经历、轨迹计算、外部资料、判断和拟拍计划。地点有设施不代表用户使用过；地图可以解释位置关系，不能代替现场经历。轨迹记录跨度与实际徒步耗时分开，距离和爬升不单独用于推断难度、疲劳或新手适用性。

作为当前攻略建议使用的价格、交通和开放信息，核对适用时间；尚无依据时保留待核实或当次经历的表述。事实缺口不能用叙事安排补造。

### 4.4 默认先交叙事大纲

主目标、素材范围和最小简报明确后，首轮交付大纲：暂定片名、观看理由、段落顺序、每段讲什么及观众获得什么、画面来源与插件内制作方式。大纲不提前展开逐字旁白、相机参数或秒级时间线；已有采用的大纲或用户当次直接要求脚本时，继续相应阶段。

路线攻略先建立全线与实际分段的骨架，再沿行进顺序介绍。景观、服务和背景在经过相应位置时穿插；挑出哪些节点简短带过、哪些值得停顿，而不是把景观、补给、人文拆成反复跳转的专题。其他视频目标按其叙事需要组织，可参考[七种结构](skill-drafts/travel-video-script/references/narrative-structures.md)。

篇幅按用户希望突出的内容安排。精华路段可以保留更多风景、行走与路线推进时间，同时减少重复旁白；交通和其他路段简洁交代，保留攻略判断需要的信息。画面时长、口播量和信息量分别考虑，不按路段或节点平均分配。

背景只选有助理解当前路线的内容。位置介绍接在开场之后，景观与人文随沿途节点简短穿插；未核实的地名来历、年代、传说或新经历留到文末待补，不为丰满结构自行补写。

### 4.5 细化口播、沿途介绍与场景清单

在用户要求的脚本阶段，沿用大纲写出适合口播的正文，再把它对应为场景。每个场景记录稳定编号、表达目的、旁白与屏幕信息、主体画面、来源与素材状态、地图编辑器方案、动画/合成动作，以及待核实或待确认事项。具体写法参考[大纲与脚本交付模板](skill-drafts/travel-video-script/references/deliverables.md)。

#### 开场：钩子、路线与观看收益

完整视频先给观众一个继续看的理由。结合用户的讲述习惯，可以用熟悉的梗、贴近观众的问题、代表景观或真实个人推荐开场，紧接本片讲哪条路线、能讲清楚什么。需要选择风格时给少量候选，用户选定后直接沿用。

口播按自然说话写。资料负责事实依据，创意先明确表达目的，再设计画面并检查素材缺口；目前有哪些照片不决定开场只能怎样写。来源、口径与核实状态放在制作说明或必要的屏幕提示中，观众需要知道的适用条件仍要讲清。客观排名应有来源，第一人称经历与评价用用户确认内容；网络玩笑不作为难度、人群比例或用户经历的证据。

#### 总览：路线数据，再讲实际分段

按用户的介绍习惯先交代路线规模，优先检查路线长度、累计爬升、累计下降、最高海拔和最低海拔，再按实际分段说明“从哪到哪、以什么路况或景观为主、精华在哪里”。分段数量由真实路线和用户经历决定，不套固定三段。

数值统一使用已确认的统计口径，口播可以取整，制作依据保留原值；屏幕精度按可读性安排。轨迹最高海拔与山峰公开海拔分别处理，实际行走时间与记录跨度分别处理。缺失指标留待核实，其他统计按用户要求取舍。总览概括范围与特点，详细经历和路面变化留到经过相应位置时再说。

画面选择服务于这些信息。3D沙盘适合全线、爬升、山脊起伏及下山关系；二维地图适合位置与走向。用户已指定画面方式时直接沿用，具体构图和运镜仍需对应场景清单。

#### 沿途：标注依次出现，重要点停顿

用户要求按位置介绍时，沿当前真实路线推进，标注按行进顺序出现。展示范围沿用标注编辑中可见的主节点：隐藏点不显示，分组只显示组节点，成员不重复弹出。节点尚未确认的位置回到信息整理流程处理。

普通点用短地名或一句带过；重要点停顿，集中讲一两项有用内容，例如山脊起伏、补给住宿、路况切换、抵达与简短背景。重要点由本次路线和用户关注点决定，不要求每个点同样时长或都读一段介绍。相同路况与服务特点集中说一次，照片、实拍、现场声和风景留白随当前位置穿插。

**依次展现标注不等于逐点核图。** 从已有索引选择重要停顿点和实际采用的少量代表素材；普通点用已确认位置与名称即可。镜头中的地点与所讲位置对应，推进到后面的节点后不无意回跳前面的地点重复介绍。

#### 交通：到达起点与入口现场

信息较多时拆成两个画面：先用地图导航形式解释从车站等出发点到徒步入口的道路距离、预计车程和交通价格，再切入口实拍或照片介绍缴费、进山准备与注意事项。具体项目可调整画面数量；目的地应落到真正的登山入口，核对同名村口、车站及游客中心的区别。导航所需的真实道路数据另行取得，能力与转换流程见[导航数据与导航画面](#导航数据与导航画面分别处理)。

道路距离和预计用时使用同一组起终点的真实导航结果，记录路线、查询日期与适用交通方式；拼车等待不混入驾车时间。用户费用经验、历史出行车程和当前导航结果分别归属。缺少道路数据时保留待核实，不用徒步里程、直线连点或其他入口的数据填充。入口收费与开放信息按适用日期核对，注意事项只保留本片需要的内容。

#### 结尾：用户的体验与经验

路线攻略收尾可用用户自己的感受、最有用的经验、行程安排取舍和推荐理由。正文已经讲清的统计、分段、交通与补给不必再完整复述。总体体感与对新手或单日/多日安排的建议来自用户确认内容；建议的行程和期待的风景与本次实际经历分别处理，不自动补写住宿、露营或看到了云海日出。画面用实际风景或用户现场镜头收束，少量字幕承接经验，给最后的评价留空间。

#### 制作前确认

先交付可审阅的脚本和逐项对应的场景制作清单，确认讲什么，以及画面、素材、镜头、动画/合成与缺项。**两项都经用户明确确认后，才开始生图、制作动画、调整并录制地图镜头、生成声音或合成视频。** 文本修改、资料检索和只读能力核查可以继续。

已有确认的指定版本与范围直接沿用，不重复询问。大纲方向、某句口播、某种画面方式或技术样片的确认不扩大为整片通过；只确认开场不代表其他场景已确认。用户要求继续流程时，先完善未展示的确认稿，不把尚未确认的方案标为已采用。

时长先按阅读和镜头需要估算，标明未试读或预览；全片分钟数、精华段比例和地图数量由当前项目决定，旧模板只作参考。

### 4.6 综合安排素材、动画与地图录制

从大纲阶段写清表达需要和制作方式，按4.5的确认流程通过后再执行。每段选择能说明路况、空间关系、景观、背景或实用信息的画面，不要求每段使用全部模块。

| 模块 | 适合承担的任务 | 制作方式与产出 |
| --- | --- | --- |
| 二维地图 | 区域位置、整线走向、重要节点及到达交通 | 调整视野与标注，在地图镜头编辑器编排相机、路线绘制和图层，导出静帧或片段；驾车线路先取得真实导航数据 |
| 3D地图 | 结合真实地形解释爬升、山脊和下山关系 | 开启地形，安排相机关键帧，预览后导出地图片段 |
| 3D沙盘 | 全线总览、路线贴地位置、起伏与分段衔接 | 在统一镜头工作台选择 3D 沙盘，编排相机、路线和地名，输出可剪辑片段 |
| SVG标注 | 分段图卡、节点说明、照片布局与辅助动画 | 调整样式和排版，保留源稿；在导出副本上制作路径描画、节点出现等动画 |
| 资源图片 | 风景、路况、节点介绍和配图 | 保留比例与来源，安排必要的淡入淡出、轻微推拉或局部强调 |
| 资源视频与声音 | 行走、人物过程、景观细节和现场体验 | 选取相关片段与声音，在实际支持的合成工具中剪辑、混音、叠字，保留引用记录 |

#### 地图镜头先在编辑器调整

按已确认的场景方案，在统一镜头编辑工作台选择地图或 3D 沙盘，调整真实路线范围、该场景的相机参数、缓动和停顿，以及路线与地名的出现时段。核对起、中、末帧和播放过程，再导出并保留工程JSON、来源及预览记录。

独立合成层承接地图/沙盘片段、照片与SVG动画、字幕和声音。需要改变地图构图或运动时回到镜头编辑器，不在合成层随意重画地形和路线。按已确认的需求先预览基础镜头，再组合讲述方式；旧样片与案例仍是候选。

#### 导航数据与导航画面分别处理

当前源码能力（2026-10-07核对）：镜头工程可包含额外道路坐标，支持路线描画、车辆标记和镜头跟随，通过兼容工程JSON导入后在现有编辑器调整并导出。当前没有输入两个地点自动规划驾车路线、距离和用时的接口，工程导入也不是任意导航文件直接导入。

因此，道路导航片段按“取得并核实导航道路、距离和预计用时 → 转换为兼容镜头工程 → 编辑器调整镜头 → 导出供合成”处理。核对坐标系，保留道路来源与查询日期；导航规划与用户实际乘车轨迹分别标明。可用现有地图制作导航画面，数据尚未取得时把缺口记在清单中，不先生成一条猜测的道路。实施前复核目标运行环境的实际能力，相关入口见[地图集成说明](geomotion-integration-plan.md)。

#### 素材、工程与来源

当前地图与三维镜头均支持无声WebM输出；SVG编辑器负责静态排版和SVG/PNG导出，逐元素动画另行制作。外部视频与音频在资源库中可预览和记录用途，完整剪辑、混音与合成由实际可用工具承接。素材已入库、静态图已导出、工程已保存和片段已录制分别记录，按实际完成状态交付。

路线保留真实连续分段，不跨断点补造连接。名称、说明、照片关联与真实坐标在标注编辑中维护，SVG只调整样式、排版和图片布局，动画使用副本；地图保留来源署名，区分斜视地图、真实地形与艺术示意。

场景清单使用稳定编号，对应完整内容中的位置背景、交通、分段经历、重要节点、住宿补给、下撤返程和结尾。每项关联来源资源/点位、文件、编辑器操作、动画/合成动作、预期产出与实际状态。确认后的变更只重做受影响任务；候选素材、已选素材、待制作工程和导出片段分别记录。


### 4.7 录制片段并准备声音与字幕

按已采用的镜头计划和当前可用工具录制或导出，记录工程、来源素材、分辨率、帧率、时长、格式及相机或时间线设置。判断录制是否可用要查看实际视频和解码画面，不能只依据编辑器预览。

已有现场声、用户录音、后期配音、拟用音乐和后制声音分别管理。先结合画面和素材确定声音安排，再制作相应配音、音乐及字幕；不把拟制作声音写成现场原声。沉浸段落可以无旁白。

执行前核对本次环境支持的录制、音频、字幕和合成方式。用现有组件完成可支持的部分，需要其他工具完成合成时保留可剪辑片段和工程，不把地图单镜导出称为完整成片。格式转换按实际文件执行，不仅更改扩展名。

### 4.8 合成、预览与成片交付

按已采用的方案组合实拍、照片、图卡、轨迹镜头、声音和字幕。检查整体节奏与各段衔接，避免地图画面、口播和屏幕文字重复堆叠。标题、开场承诺和结尾应兑现同一个主目标。

实际预览和检查输出：路线方向及节点、分段路况、中文地名、数字与单位、字幕可读性、声音同步、音量、黑帧或缺素材、结尾画面，以及需要保留的来源署名。核对文件格式、尺寸、时长与实际帧率；失败或明显错误修正后再交付。

只有实际完成导出并查看过的文件才标为成片。若当前任务交付的是大纲、脚本或素材包，按该阶段标明完成范围，不用计划中的后续制作充当已经完成的结果。

## 五、分阶段交付模板

| 阶段 | 核心交付 | 需要保留的依据 |
| --- | --- | --- |
| 大纲 | 简报、观看理由、段落顺序与衔接、背景介绍位置、插件内素材与动画制作安排、轨迹作用 | 主目标、素材范围、关键事实与背景来源、资源与待定项 |

| 场景制作清单 | 与脚本逐项对应的表达目的、主体与辅助画面、素材来源、地图编辑器方案、动画/合成方式和缺项 | 脚本与清单的版本、用户确认状态和确认依据；两项通过后才执行 |
| 试镜与素材 | 地图/沙盘样片、SVG 动画或图卡、图片/视频引用清单与工程 | 原始素材到输出的关联、操作和动画设置、候选或已采用状态、实际检查结果 |

来源、素材索引与工程记录放在缺项清单之前。「待补充与待核实」统一放在文末，区分用户需补充的真实经历和素材，以及 Agent 需检索、核实或制作的事项。交付后主动提醒最影响下一阶段的缺口，并说明关联段落与用途；已经补充的内容不重复索取。

## 六、武功山试跑：本项目选择示例

以下记录用于说明通用写法如何落到一次项目，不作为其他路线的固定模板。当前主目标是“帮助观众判断怎么走、怎么安排”，规格为横屏完整攻略，木马坳—金顶保留更多画面时间。全片脚本与场景制作清单仍在审阅，未固定总分钟数。

| 部分 | 本轮采用的方向 | 当前确认范围 |
| --- | --- | --- |
| 开场SC01 | 第1版“青春没有售价，直达武功山下”，接武功山反穿与攻略收益 | 第1版开场旁白已确认；具体画面与过渡待审阅 |
| 总览SC03 | 先长度、爬升、下降、最高/最低海拔，再讲龙山村—木马坳、木马坳—金顶、金顶—石鼓寺三段；按最新反馈与SC04A共用真实地形3D地图，通过镜头调度衔接 | 顺序、3D地图与切换方向已确定；具体口播、相机参数和统计排版待审阅 |
| 交通SC04A/B | 第一画面承接SC03的同一3D地图，镜头拉远、转向车站，再沿真实驾车道路到龙山村入口，配距离/车程/拼车价格；第二画面为入口缴费和注意事项 | 两画面、3D地图及镜头切换方向已指定；OSM/OSRM道路约51.3km、模型预计约52分钟已核实，无实时路况；具体镜头仍可审阅调整 |
| 精华段SC06—SC11 | 沿位置连续介绍，标注依次出现；普通点简短带过，重要点停顿；短旁白与更多风景时间并存，一直介绍到金顶 | 叙事与节奏方向已明确；具体新旁白、镜头和停顿待审阅 |
| 结尾SC15 | 用户体验与经验：反穿强度、单日/两日选择、天气和装备准备，最后表达值得去的评价 | 用户已提供总体体验；新口播与画面待审阅 |

精华段的当前可见主节点顺序是：**木马坳 → 发云界 → 风车口 → 千丈岩 → 好汉坡 → 武发客栈 → 赤脚拗 → 绝望坡 → 望日山庄 → 观音宕 → 吊马桩 → 金顶**。拟在绝望坡讲起伏、观音宕讲服务、吊马桩讲路况切换、金顶讲抵达与简短背景；风景留白沿途中穿插。隐藏节点不自动加入，分组成员不重复出现，也不为每个标注重新核查全部照片。

40元/人拼车与10元/人入口清洁费属于用户当次经历；本次未另购大门票，不作为后续免票政策。导航已按本次入口坐标取得真实道路，约51.3km、OSRM模型预计约52分钟，无实时路况；旧起始时间异常不用于本视频规划。

本地完整脚本、场景制作清单及历史技术样片保存在本次工作区的 `outputs/video-script-trials/`，不随源码发布。已实现的[位置介绍镜头示例](../examples/wugongshan-location-preview/README.md)和[路线基础资料](track-information-wugongshan-example.md)用于复用与核对；局部镜头预览的制作授权不扩大为全片确认。
