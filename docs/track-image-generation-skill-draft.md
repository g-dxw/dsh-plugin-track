# 轨迹图片创作 Skill 草稿

版本：v0.1  
整理日期：2026-10-07  
状态：独立讨论稿，尚未创建、安装或启用正式 Skill。本轮只整理流程；图型、视觉风格与具体执行方式继续讨论。

## 一、目标与职责

根据已整理的路线资料和用户的图片需求，选择合适的信息与素材，形成生图方案、提示词和图片，供路线介绍、攻略、视频封面或其他明确用途使用。

本草稿与[轨迹信息整理 Skill 草稿](track-information-skill-draft.md)分开：信息整理负责资料提取、地点确认、来源与缺项；图片创作消费这些结果，负责内容取舍、视觉表达与生成后的核对。地点有疑问时返回位置确认流程，图片创作不直接修改轨迹、标注点或分组。

现有武功山示意图仅为探索结果。具体画风、布局、图型和信息密度仍需根据用途确定，不作为通用模板。

## 二、输入资料

| 输入 | 用途 |
| --- | --- |
| 用户的图片任务 | 明确给谁看、在哪里使用、主要表达什么；沿用已说明的要求 |
| 路线资料 MD | 提取与本次图片有关的统计、分段、节点、背景及实用信息，并保留来源与确认状态 |
| 原始轨迹与当前点位 | 有准确路线或地点要求时提供真实几何、方向、节点与分组依据 |
| 用户选定的照片或已有图片 | 按任务提供主体、地点外观、构图或视觉参考；编辑任务还需指定被编辑的图片 |
| 已有模板与提示词 | 复用结构或表达方式；根据本次资料适配，保留原模板与当前草稿 |

只读取与本次任务有关的资料。先做内容筛选，不把整份路线 MD、全部点位和全部素材直接堆入生图提示词。

## 三、执行流程

### 3.1 明确图片任务

先确定用户希望图片解决什么问题，再选择图型。例如：帮助理解路线结构、比较各段路况、记住关键节点，或用于吸引观众打开视频。

复用对话中已经明确的用途、图型与风格。只缺少局部要求时，补齐会影响结果的关键项；用途或图型尚不清楚时，先整理素材范围和图片方案，再集中向用户询问，不自行把任务固定为路线信息图。

最小任务说明包括：用途与受众、主要表达内容、图型、需要的文字与数据、视觉参考、画幅或使用位置。只填写实际相关的项目；没有必要固定为统一问卷。

区分当前交付要求是「方案」「提示词」还是「图片」。用户只在讨论可行性、编写草稿或优化提示词时，交付相应结果；明确要求出图且信息足够时，按已有授权执行，不重复设置逐步审批。

### 3.2 选择上图内容

围绕本次主目标，从路线资料中选出必要信息，形成「上图内容清单」：正文、数字、节点与顺序、需要表达的路况或景观，以及各项的来源和确认状态。

- 路线统计采用一致口径，说明单位与必要的取整方式。
- 分段路况与用户评价保留其来源，区分山路、土路、台阶、树林和草甸等实际差异。
- 已确认地点用于相应表达；未确认地名按任务保留候选状态或暂不采用，不能在图中转成确定位置。
- 动态价格、交通班次和开放信息核对适用时间；对主要表达没有帮助的内容可留在资料文档中。
- 每张图承担清楚的表达任务。内容较多时提出拆图建议，由用途决定，不固定图片数量。

### 3.3 准备图片与位置依据

先读取用户选中的实际图片，再说明每张图的角色：主体参考、地点外观参考、构图参考、风格参考，或需要编辑的原图。不能依据文件名、图片编号或模板标题猜测内容。

主体参考用于人物、装备或景物特征；风格参考用于色彩、光线、氛围和表现手法。模板案例中的地点与人物不自动变成本次路线素材。图片可帮助表达外观，地点名称与位置仍以轨迹资料和确认结果为依据。

需要准确路线地图时，先用原始轨迹与真实节点确定路线几何及位置，AI 可处理视觉表现。单靠文字生成的线路只能作为示意，不能作为准确导航线路。SVG 排版位置与真实坐标分开；展示哪些节点、分组或隐藏点，沿用当前任务采用的标注范围。

### 3.4 形成生图方案与提示词

先把图片方案写清楚，再转成提示词。方案包含：

1. 图片的用途、主题与图型。
2. 要表达的内容，以及主次关系和阅读顺序。
3. 布局、画幅、视觉表达与参考图角色。
4. 必须保持准确的文字、数字、路况、节点和路线关系。
5. 允许艺术化的部分，以及图片能表达的事实范围。

提示词说明主体、内容、构图、风格、文字和约束；编辑任务明确修改目标与保留内容。需要上图的中文文案先精简并确定，文字与节点对应，避免为了装饰补入未提供的地名、标语、设施或行程经历。

用户要求只出方案或提示词时，此处即可交付；需要图片时，沿用已明确的方案与生成授权继续执行。要求缺失且会改变图片主目标时，先解决该缺项，再执行依赖它的生成。

### 3.5 生成与调整

使用本次任务选定的生图工具或既有图片创作入口，保留输入资料、参考图角色、提示词和输出之间的对应关系。复用当前模型、参数和用户要求，不因重试自行改变主目标或参考素材。

生成后先核对事实与表现，再根据用户反馈调整同一任务。局部问题尽量局部修正，保留已采用的内容；方向变化时更新图片方案。失败或取消时保留原提示词和参考图，交代当前结果，不用未读取的素材补造替代版本。

### 3.6 核对与交付

成图核对至少包括：

- 中文地名、文案、数字、单位及统计口径。
- 行进方向、节点顺序与分段对应；准确地图另核对真实几何和位置。
- 路面、地形、植被与景观是否符合采用资料，画面有没有把不同路段混成同一种路况。
- 人物、装备或地点外观是否符合本次主体参考；没有把地点提供的服务画成用户实际经历。
- 布局与信息密度是否服务于本次用途，文字是否可读。

发现影响理解的错误，针对错误修正并回看；仍无法核对的部分明确其范围，不宣称准确。交付图片和可复用的最终提示词，保留必要的来源、版本、参考图与结果记录。原图和素材保留；文件位置按本次任务的交付范围确定。

## 五、武功山的讨论示例

已整理资料可支持以下方向，选择哪种取决于用户想表达什么：

| 图片方向 | 主要解决的问题 | 可采用的资料 |
| --- | --- | --- |
| 三段路况对比 | 理解一路的行进与景观变化 | 龙山村—木马坳树林爬升、木马坳—金顶草甸山脊、金顶—石鼓寺台阶下山 |
| 路线结构图 | 理解怎么走、关键节点在哪里 | 真实轨迹、已确认节点、方向和当前分组；准确地图使用实际几何 |
| 节点介绍图 | 了解某个地点的作用或外观 | 已确认地点、相关背景与用户选定照片；例如观音宕的住宿与营地服务 |
| 视频封面 | 突出视频主题和观众收益 | 已确定的视频目标、精选素材及简洁标题，不自动塞入全部统计和攻略 |

这份示例只列内容方向，不预先确定图片样式或采用其中某个方向。

## 六、后续讨论重点

- 图片参考、真实轨迹底图与纯文字生图如何组合。
- 多图拆分、文字密度、风格和尺寸的实际要求。
- 提示词如何交给现有图片创作组件，以及生成结果如何保存和复用。
