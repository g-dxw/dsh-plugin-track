# 徒步与旅行视频脚本创作规范

状态：待定草案 v0.5。整理日期：2026-10-04。暂存于文档目录供评审，尚未安装或启用为 Skill。

依据用户提供的《徒步、旅行攻略视频叙事调研》整理。七种结构属于该材料的创作归纳，示例台词属于拟写文案。本文不沿用其中未经重新核验的播放量、原片顺序或不可解析的引用索引。

## 1. 创作目的与适用范围

先确定观众为什么观看，再用旅程逐步兑现这个理由。

用户已选择徒步实测攻略目标时，可采用：**带着一个问题去实测，用路线推进故事，最后交付一份有条件的方案。** 这是一种优先考虑的组合，不是所有影片必须采用的形式。

| 主目标 | 观众获得什么 | 脚本验收重点 |
| --- | --- | --- |
| 攻略 | 能做一次出行判断 | 适用条件、路线安排及理由、时间与费用代价、退出或返程、备选方案 |
| 旅行故事 | 跟随一次真实经历 | 目标、真实变化、选择、结果，以及理解如何改变 |
| 沉浸同行 | 感受一次连续的旅程 | 空间推进、环境与身体体验的变化、声音、停顿和离开后的回落 |
| 风景宣传 | 看见路线的吸引力，产生了解或前往的兴趣 | 代表性景观、清楚的体验期待、必要地点信息及有依据的条件 |

每稿先由用户确定一个主目标，必要时声明辅助目标；上表是常见选项，用户也可以自行描述目标。按主目标验收；攻略信息缺失不能用风景镜头抵消，沉浸内容也不必强加口播问题和戏剧冲突。

主目标与素材范围确定后，默认先交付叙事大纲，让用户先确定主题、段落顺序和内容取舍；用户后续明确要求细化时，再进入旁白与分镜脚本。用户说“先不要脚本”时，当前交付止于大纲，不附示例台词、逐镜卡片或秒级时间线。已有明确采用的大纲无需重复确认；用户当次明确要求直接写脚本或只修改某一层级时，按其要求交付。写脚本的授权不自动包含录制、配音、合成、发布或安装技能。

## 2. 规则强度

**必须遵守：**先确定用户主目标，再确认素材范围并据此创作，按大纲与脚本阶段交付；事实不虚构，条件不隐去，结论可追溯；分别标明已有素材、外部参考、拍摄计划及待核实信息；遵守用户指定的类型、风格和范围。

**建议采用：**一个主要观看问题、一种主结构、关键节点的小闭环；地图与现场素材分工；攻略兼顾体验结束与决策交付。

**按项目调整：**平台、时长、段落占比、口播密度、镜头数量、地图比例、节奏与文风。7 分钟或 60–90 秒只是示例，不作为流量公式或验收阈值。

## 3. 先确定主目标，再确认素材范围与最小简报

顺序：**用户主目标 → 素材范围 → 最小简报 → 大纲 → 后续按要求细化脚本。** 已经明确的选择直接沿用。

### 3.1 首先让用户确定主目标

开始新的创作时，先检查用户是否已明确希望观众获得什么。尚未明确时，第一问是：

> 这次你想创作什么类型的视频？希望观众看完最主要获得什么？

给出上述四种常见选项，并用观众收益解释：路线攻略帮助判断怎么走、怎么安排；旅行故事讲述经历、选择与变化；沉浸同行让人跟着风景与现场过程体验旅程；风景宣传展示路线吸引力。允许用户自行描述，也可在明确主目标后搭配辅助目标。不要预先标出推荐类型或替用户选择。

用户已说“做一条路线攻略”等明确要求时直接沿用，不重复询问。仅有目的地、轨迹、素材数量，或“Vlog”“电影感”等形式描述时，根据需要问清观看收益，不自动认定攻略或沉浸同行。

主目标未定时可以读取路线和整理事实，但不先生成大纲、不选叙事结构；先解决这一项，不同时追问平台、时长、风格等一串设置。

### 3.2 再确认素材范围

主目标确定后，若用户尚未说明素材范围，再问：

> 这次脚本的素材是否只局限于当前轨迹素材？

提供两个选项：

| 选项 | 创作依据 | 素材缺口怎样处理 |
| --- | --- | --- |
| **只用当前轨迹素材** | 当前路线、已保存点位与说明、关联照片/视频/声音，以及用户已提供的相关经历 | 以已有证据组织内容；调整表达、替换或删减无法支撑的段落，列出必要缺口 |
| **不局限当前轨迹素材** | 结合路线理解与按需检索的网上资料设计内容；用户提供相关照片、视频、声音或经历，轨迹用于必要的空间解释 | 先给出叙事大纲与素材类型需求，后续再细化分镜；缺少的实拍素材列为用户待提供/待补拍，轨迹插镜列为设计方案 |

这是创作范围选择。用户已明确“只用现有素材”或“可以参考网上资料”等要求时直接沿用；同一脚本后续修改保留已选范围，除非用户改变。不要每次改稿重复询问。

范围尚未确定时，可以先读取路线和整理本地素材；等待选择后再开展依赖该选择的资料扩展与脚本正文。不能把用户未表态自动解释为只限当前素材，也不能据此擅自扩展。

### 3.3 提取最小简报

从现有对话和资料提取以下信息，不重复询问已经明确的内容：

- 用户已选主目标及选择依据、辅助目标（有则写）、已选素材范围、目的地或路线、目标观众及他们最关心的问题。
- 拍摄前策划还是拍摄后剪辑；已有轨迹、照片、视频、现场声音、笔记或采访。
- 发布平台、目标时长、表达风格，以及用户明确要求保留的内容。
- 已知拍摄日期、季节、体力或预算条件，以及影响方案成立的限制。

先写一句创作命题：**给谁看，回答什么，凭哪些材料，观看后获得什么。** 沉浸片可把“回答什么”写成要体验的空间过程，不强制用问句。

缺少风格、平台或时长时，可采用暂定设置并标注；缺少关键事实时，继续完成可确定部分，用明确占位符保留缺口。只追问会改变主目标、核心结论或关键安排的问题。不能用创作假设填补事实缺口。

### 3.4 素材由用户提供，助手负责脚本设计

扩展模式默认按以下分工开展：

- **用户：**提供可用照片、视频、现场声音和相关经历，或补充脚本需要的实拍素材。先了解已有素材概况，不要求所有素材到齐才能出稿。
- **助手：**设计选题、叙事、大纲、旁白、分镜及素材需求；可查资料帮助理解路线，网上资料作为写作参考，不等同于助手负责找齐成片画面。
- **轨迹镜头：**在需要交代位置、起伏或路段衔接时融入，作为辅助插镜。用户要求旅行叙事时，主体由风景、人物与现场过程承担，不把全片变成逐点报幕或地图回放。
- **交付：**先给大纲及简明的素材类型需求，说明每个段落讲什么、怎样衔接、哪里需要轨迹辅助。用户明确要求进入脚本阶段后，再细化旁白、分镜和逐项素材需求。仅设计内容时，不自动下载素材、生成画面、录制或合成视频。

地图数量与秒数按需要设计，避免每段都插地图；用户明确要路线说明或纯轨迹视频时遵从其类型要求。

## 4. 先整理证据，再组织故事

用简短事实与素材清单记录：内容、范围来源、具体出处或素材编号、拍摄/记录日期、核验状态、可支持的结论与限制。完整脚本使用事实编号，便于分镜引用。

主目标明确后，扩展模式先理解当前路线的方向、节点和实际记录范围，再围绕该目标确定值得讲述的主题。可补充路线背景、景观特点、沿途地点、文化线索、行程取舍与拍摄场景；先设计观众想看的内容，再对应用户素材和必要的轨迹插镜，不由本地照片数量或地图能力决定全片结构。

路线理解用于提出选题、判断与画面设想；涉及具体地名、历史、景观条件、设施及行程的事实时，根据可用证据核实。网上资料记录具体链接、作者或机构、资料日期与核验日期；优先采用可靠的直接来源，个人游记只代表其记录条件下的体验。核对路线版本、行进方向、相关路段与季节，避免把另一条同名路线的结论套到当前轨迹。来源不一致时说明差异，尚未核验的理解标为推断或待核实。

外部文章提供信息，不代表文章中的图片或视频已成为可用剪辑素材。事实来源与画面取得状态分别记录。

区分四种信息：

- **事实或计算结果：**说明依据、计算口径和状态；用户提供的信息不自动视为已外部核验。
- **个人体验：**明确是哪次旅程、哪位参与者的体验，不推成所有人的结论。外部游记不改写为用户本人实测；第一人称已发生经历使用用户确认的内容。
- **判断或建议：**写明适用人群、条件和依据；依据不足时缩小结论。
- **创作计划：**拟拍画面、示意对白和拟用地图，明确属于提案，不写成已经发生。

具体边界：

- 轨迹记录跨度不等于实际步行时间或普通人的预计耗时；影片时间与旅程时间独立。
- 距离、爬升和照片不能单独证明“新手适合”、技术难度、疲劳程度或危险性。
- 采样最高点不自动是山顶；停留点不自动是休息或补给设施；轨迹起点不自动是集合点。
- 不从轨迹或风景照片编造天气突变、岔路决策、人物对话、失败、事故或感悟。
- 价格、交通、预约、开放和通行条件在作为当前攻略建议使用前核实，并记录核验日期；无法核实时标明待核实或仅作为当次经历。
- 影响出行判断的关键限制放在观众需要决策之前，不留到结尾制造悬念。
- 引用人物原话需要可追溯素材；不得把拟写台词冒充采访，也不得扭曲人物原意来完成预设主题。

资料不足时按已选模式处理：

- **只用当前轨迹素材：**优先缩小承诺、改选结构，或用已有材料和明确标注的示意画面完成讲述。
- **不局限当前轨迹素材：**可以参考路线理解和外部资料；大纲阶段保留完整叙事方向，进入脚本阶段后再展开镜头方案，列出用户待提供/待补拍素材、后续制作与核验事项。本地缺图不要求退回路线复述，也不要求删除有价值的创作段落；缺少实拍时不自动用大段轨迹回放填满。
- **两种模式共同：**事实不足时收紧具体断言或标注待核实；画面不足时标明制作状态。地图可以解释关系，不能替代尚不存在的现场证据。

扩展模式中的日出、云海、采访或行动变化，可以作为条件性拍摄目标、访谈计划或创意提案；不能写成用户已经看见、遇到或完成的事实，也不能保证自然景观必然出现。

## 5. 选择叙事结构

选结构或改结构时读取 [七种结构与选择条件](references/narrative-structures.md)。确定主结构并简述它与观众需求、素材条件的关系；辅助结构只在改善交付时加入。

用户已选徒步实测攻略目标时，可优先考虑：行程交付作骨架、真实目标推进过程、沉浸段落兑现体验。当前素材模式缺少真实变化时允许平稳推进，缺少人物材料时不编人物故事；扩展模式可设计目标、可能变化、采访问题及相应镜头，明确其为拍摄策划，不预写虚构经历或采访答案。

预期验证先写判断标准，再整理正反证据。拍摄后才形成的标准如实说明，不能写成出发前已设定。方案取舍交代各方案代价，不能只替自己的选择辩护。

## 6. 从段落推进到分镜

大纲阶段先确定开场承诺、必要条件、关键节点和结尾交付。每个重要段落用简短文字说明：讲什么、让观众获得什么、如何接到下一段；附所需素材类型及轨迹插入位置与作用即可。不要把大纲展开为可直接朗读的旁白、逐镜卡片、相机参数或秒级时间线。

提交大纲后按用户反馈调整方向；用户要求继续细化时，才拆分镜头。已经确定的内容直接沿用，不为每个段落另设确认步骤。

用“当前目标 → 现场情况 → 判断或行动 → 小结果”检查决策节点。用“因为—但是—所以”检查真实因果；不要求每段口播照念这些连接词，也不要求每个风景镜头都有冲突。

风景让人想去，代价让人判断，选择让过程推进。交通和住宿只有在解释条件、取舍或经历时展开；不因拍过就保留机场、酒店或吃饭片段。

攻略结尾完成两项交付，可分开也可合并：

1. **体验收尾：**抵达、完成、折返或接受计划调整。
2. **决策收尾：**实际投入、与预期的差异、适合与不适合的条件、再次安排时的调整和备选方案。

攻略目标的短视频可围绕一个问题重新组织：问题 → 关键证据 → 有条件的判断 → 路线或行动总结。不要将长攻略全部压成高速报幕。故事和沉浸片按其主目标收尾，不强制套用攻略清单。

## 7. 文案、画面与声音

旁白说明画面难以独立表达的判断、原因和条件；屏幕文字承载必要名称、数字与提醒，避免与口播重复堆叠。口语表达优先使用具体观察，少用没有材料支撑的“震撼”“治愈”“人生意义”。

叙述已发生的困难与情绪时，使用具体表现和真实记录。扩展模式可策划条件性的体验表达与待拍场景，注明提案性质。允许旅程没有反转，允许结论是“这次无法判断”。

沉浸段落允许无旁白，以行走、环境变化和声音推进。已有现场声、待补录声音、拟用音乐分别注明；不得把拟制作的声音标成原始现场声。

进入脚本阶段后，每个镜头分别写清叙事任务、画面、相机/剪辑、旁白、屏幕文字、声音、素材状态和事实依据。无口播、无地图或无屏幕字时可以明确留空。细节使用 [交付模板](references/deliverables.md)，无需为简单请求展开大表。

## 8. 地图与三维轨迹的叙事职责

旅行叙事中的轨迹镜头采用少量辅助插镜：在观众需要空间解释时进入，完成任务后回到用户实拍。先设计整体叙事，再安排轨迹，不逐段默认附加地图。每次使用地图，说明它帮助观众理解什么，优先用于：

- 出发时建立目的地、起终点、线路全貌与周边关系。
- 进入关键路段前解释爬升集中位置及路段关系；不据此直接推定技术难度。
- 面临真实选择时对比岔路、绕行、退出或返程方案。
- 结束时连接已讲过的节点，回顾完整旅程或行动方案。

地图镜头分开描述**讲述任务**与**基础运镜**。按任务选整线描画、定点展示、全景推近点、点拉远到全景、沿线跟随或局部展开；不为展示运镜而添加无信息的地图段落。

路线断点、方向、点位和地名保持与证据一致；不跨断点伪造连续道路，不推定未经确认的山峰名称或位置。区分二维地图斜视、真实地形三维图和示意画面。

大纲阶段仅标注轨迹插入的段落与作用；脚本阶段再写轨迹镜头的任务、位置和预计时长，不自动执行预览或录制。后续用户要求实际试镜时，在 Track 中沿用“先预览基础镜头，再组合讲述方式”的约定。案例保持候选状态，只有用户明确采用后才进入正式脚本；不增加逐步确认流程，也不撤销已有明确采用授权。

需要对接 Track 时，再查看 [现有脚本约定](../../track-video-script.md) 和 [镜头案例约定](../../track-shot-cases.md)。本草案不改变当前应用的数据格式或实现。

## 9. 交付与自检

按当前阶段交付，模板见 [大纲与脚本交付模板](references/deliverables.md)：

- **大纲阶段（主目标与素材范围已确定后的首份内容交付）：**暂定片名、核心观看理由或体验主线、主结构、段落顺序及内容、少量轨迹插入位置与作用、用户素材类型需求和必要的待定项。交付到此，等待后续方向反馈，不附完整脚本。
- **脚本阶段（用户后续要求）：**含素材范围与分工的创作简报、逐段旁白与分镜、素材/事实来源与状态、用户待提供/待补拍素材需求、轨迹插镜安排与待核实清单，以及按主目标完成的自检。

提交前检查：

- 开场、标题建议与结尾兑现的是同一个承诺，关键条件已及时出现。
- 主目标已由用户明确，不是助手从路线或素材自行推定；既成事实有证据或真实体验支撑；扩展策划节点明确其参考依据和待拍状态，不伪装成已完成旅程。
- 时间、费用和难度表述不超出依据；主观体验与通用建议分清。
- 每个地图段落有空间或决策作用，数量服务影片目标；旅行叙事没有被大段轨迹回放替代。当前轨迹、外部资料与路线理解来源可区分，已有、用户待提供、待补拍及后续制作状态清楚。
- 大纲阶段只检查主题、段落衔接、素材分工与轨迹作用，不提前要求逐镜时长或口播文案。进入脚本阶段后，再检查分镜时长、口播、读字、运镜和必要停顿；未经试读或预览时写“估算”，不宣称已验证。
- 没有为完整文案掩盖资料缺口，没有把候选案例或补拍计划写成正式采用的成片内容。

质量与传播分开评估：播放量不证明某种结构造成高播放，留存高峰也可能意味着信息不清而重看。发布后若获得数据，结合观众反馈与实际内容定位复盘，不预设“黄金三秒”或万能节奏。

## 10. 转为正式 Skill 前的待定项

以下问题暂不阻塞草案使用，具体项目有用户要求时优先遵从：

- **定位：**通用旅行脚本 Skill，还是以 Track 轨迹攻略为主；暂按通用规则加可选 Track 约定。
- **默认风格：**讲述者人设、口播语气、情绪程度；暂按具体、克制、口语化处理。
- **默认规格：**平台、横竖屏、时长、旁白及现场声比例；暂按每个项目单独设定。
- **正式交付接口：**是否需要结构化 JSON，以及与应用镜头字段如何映射；暂用 Markdown 可审阅稿，不声明可直接导入应用。

正式化建议分别试写只用当前轨迹素材的版本与允许扩展资料的版本，再检查资料不足时能否保持所选模式的创作目标，以及沉浸片或单问题短片的表现。试写与结构检查通过不等于安装或启用。
