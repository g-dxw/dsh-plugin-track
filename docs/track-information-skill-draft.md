# 轨迹信息整理 Skill 草稿

版本：v0.7

整理日期：2026-10-07

状态：第一步「基础信息整理」已写成流程稿；第二步与第三步继续讨论。仅保存为 Markdown 草稿，尚未创建、安装或启用正式 Skill。

## 一、目标与范围

把一条轨迹的资料分块整理，让后续的视频制作、路线介绍和信息查询能够按需提取，并找到对应来源。

整体分为三个步骤：

1. 基础信息整理：本稿已明确输入、位置反推与用户确认、资料整理、输出和补充提醒。
2. 当前轨迹的标注点整理：完整点位、分组、显隐和图片等规则继续讨论。
3. 路线及标注点的背景调查：进一步的自然、人文、环境与地点调查继续讨论。

第一步先形成一份可用的路线基础资料。它可以包含重要节点的简要作用及出行所需的公开信息；完整点位资料和深入背景调查在后续步骤完善。

## 二、第一步：基础信息整理

### 2.1 目标与输入

把当前路线已有的数据、用户经历和必要的公开资料，整理成一份有来源、可继续补充的 Markdown 基础资料，供后续路线介绍、视频制作和信息提取使用。

读取当前轨迹记录、可用的原始轨迹文件、当前标注点的名称与说明、用户已提供的经历，以及已有资料文件。沿用对话中已经确认的起终点、路线方向和分段，不重复询问。资料缺失时先完成可整理的部分，把缺项放到文末。

执行顺序：**读取现有资料 → 整理路线统计 → 对未确认的相关点位反推地点并请用户确认 → 整理分段经历及实用信息 → 按需联网补齐 → 输出 MD → 提醒用户补充。** 已确认的地点直接沿用；等待确认时继续整理不依赖这些地点的内容。用户继续提供信息时更新同一份文档。

### 2.2 提取路线概况与统计

| 资料块 | 整理内容 |
| --- | --- |
| 轨迹身份 | 路线名称、轨迹编号、原始文件名称与格式；有导入日期时，与路线记录日期分别保留 |
| 路线概况 | 所在区域、起点、终点、行进方向及主要经过节点；附近地名与真正的起终点分别说明 |
| 时间信息 | 有依据的记录日期、开始与结束时间、时区、轨迹记录时长；实际徒步耗时来自用户经历或可验证记录 |
| 路线统计 | 距离、累计爬升、累计下降、最高海拔、最低海拔、运动均速 |
| 信息来源 | 各项采用的原始字段、应用统计或计算方式；有差异时说明口径与采用依据 |

先检查现有记录和原始文件中是否已有相应字段，再进行必要的计算。使用统一单位，速度优先展示公里／小时；计算值保留输入字段与公式，避免混用不同来源的距离和时长。

运动均速区分应用展示值、源文件声明值，以及能按有效移动时间计算的均速。若无法确认是否扣除休息，写明统计口径。标记时间跨度与实际徒步耗时分别记录；缺少可靠时间时不补造耗时或均速。

只保留会影响理解的缺失或差异及其依据，不把单次数据问题扩展为固定的排查流程。

### 2.3 根据位置反推地点并请用户确认（按需）

在采用起终点、分段边界或重要节点的地点名称前，检查其地点含义是否已经确认。真实坐标已有、但名称为空、名称只是编号、名称仅来自未确认的反查结果、反查结果与用户描述不一致，或分组名称不能准确表达成员所在路段时，先整理位置候选。用户已经明确确认的地点不重复核对。

1. **读取位置依据**：保留点位稳定编号、原标题与说明，读取真实经纬度、坐标系、可用海拔、当前分组及成员。结合真实轨迹的分段、沿线位置和行进顺序判断所处路段；不用 SVG 排版坐标或列表编号代替真实位置。
2. **反查候选地点**：优先复用已有位置查询资料；不足时使用可用的反向地理编码或地图地名、山峰、山口、客栈、营地等沿线对象补查。核对查询服务所需坐标系，记录候选名称、对象类别、对象编号或来源链接及查询日期。原有文字和用户经历作为辅助依据，不用图片猜测替代位置核对。
3. **结合路线筛选**：区分实际地点、附近地名及接近或离开的路段。最近 POI 只作为候选，结合距离、沿线位置、前后已确认节点、海拔变化和行进方向说明为何采用或保留疑问；距离注明直线或沿线口径。同名地点按对象及所在路段区分，不能仅因名称相同跨段归并。
4. **核对独立点与分组**：独立点按自身位置判断；分组检查各成员位置及连续路段，不用一个展示锚点确认整组都在同一地点。编号路线碑等弱名称可参考附近有明确含义的地点，但只提出归属或命名建议；候选成员需保持路线连续，不能仅因距离近就跨段合并。
5. **提交确认清单**：先把候选地点、依据和疑点整理出来，再请用户按点位或分组编号确认、改名，或说明它只是附近地名。多个候选或重复经过导致的归属疑问同时保留，查不到可靠名称时保留原名和位置范围。确认问题聚焦有疑问的地点，可分批回复。
6. **采用确认结果**：查询结果标为「推定，待用户确认」；用户确认后记录「用户已确认」及其补充说明，再用于路线概况、分段、重要节点及后续背景调查。未确认内容继续保留候选状态，文末列入「请用户补充」；相关资料可先写位置范围，不把某个候选当成确定地点。此环节只更新整理文档，不直接修改源点位或分组。

确认清单至少包含：

| 点位／分组编号 | 原有名称 | 真实位置及所属路段 | 候选地点或位置范围 | 推定依据与疑点 | 确认状态／请用户确认的内容 |
| --- | --- | --- | --- | --- | --- |

例如，起点反查返回某个附近聚落时，应区分「实际登山起点」与「附近地名」。武功山对话中已确认龙山村是起点、石堎上只是附近地名，应采用这项确认，不再按查询结果替换或重复询问。

方法可参考此前武功山的本地武功山标注位置确认记录（未随源码发布）和本地武功山标注位置确认记录（未随源码发布）：结合坐标反查、连续路段与原有名称整理地点候选。本稿补上「向用户提交候选并确认」的环节；旧方案的点位数量、分组数量及距离阈值不作为通用规则。

### 2.4 整理分段经历

采用用户给出的分段。尚未分段时，按路线节点和地形变化提出简洁的分段建议，再提醒用户补充；不把某条路线的分段数量固定为通用规则。

| 分段 | 起终节点 | 地形与行进特点 | 路面类型 | 植被、景观与用户体验 | 实际耗时与休息补给 |
| --- | --- | --- | --- | --- | --- |

每段保留爬升、下降或山脊起伏，树林、草甸等环境，山路、土路或台阶等路面，以及用户觉得精彩、疲劳或印象深刻的经历。主段内路面明显变化时，记录子段边界。可关联已有点位编号，方便后续提取。

路况与体验标明来自用户叙述；用户已提供的内容直接写入正文。缺少的实际耗时、体力感受、具体休息补给和经历列在文末，不从里程和爬升单独推出体感、难度或新手适用结论。

### 2.5 补充重要节点与出行实用信息

| 资料块 | 第一阶段整理内容 |
| --- | --- |
| 重要节点 | 名称、所在路段、已有点位编号及基本作用，如景观、山口、路口、住宿、营地、补给或索道；先整理影响路线理解和安排的节点 |
| 路线与环境概述 | 简要说明路线的代表性地形、植被和景观；来源不足的细节留给后续调查 |
| 住宿与营地 | 沿线分布、类型和条件；按资料需要补充餐食、饮水、卫生间、淋浴、供水供电等配套及费用 |
| 补给 | 分布、可购买的品类、价格特点和用户实际购买记录；结合用户的体力、行程和负重整理携带考虑 |
| 入口与费用 | 登山入口、现场缴费位置、用户实付及公开购票规定；说明适用日期或条件 |
| 索道与下撤 | 名称、分段范围、上下行方向、票价和步行衔接；有依据时列下山时间参考或备选下撤方式 |
| 到达起点 | 出发车站或地点、到徒步起点的交通方式、拼车或班车费用、乘车与换乘点；有资料时补车程和班次 |
| 离开终点 | 徒步终点到游客中心或交通枢纽的衔接、返回市区或车站的方式、费用及返程班次 |

节点的简要作用属于第一步；全量点表、分组成员、隐藏点位和图片处理留给第二步。

用户关于路线成熟度、客栈条件、补给价格、拼车便利程度和精华路段的描述，保留为其经历或判断。地点有住宿或露营服务，只说明可提供的服务，不扩展为用户已经入住的经历。

交通核对出发地与目的地，区分普通火车站、高铁站、徒步起终点和游客中心。去程与返程、常态班次与临时加班分别核实，不能把某个方向或某次活动的时刻写成通用安排。

### 2.6 按需联网补齐与记录来源

先使用现有资料与用户已提供的信息，再围绕缺少的重要节点、交通、住宿补给、入口与索道等基础内容开展有针对性的检索。优先采用景区、交通运营方、政府、经营者等直接来源；其他报道、平台信息或游记注明来源身份。

每条可提取的资料关联路线或点位，并区分：

- **轨迹与原始记录**：字段来源或文件位置。
- **计算结果**：参与计算的数据、单位与公式。
- **用户经历**：本次实际情况和用户评价。
- **外部资料**：链接、发布日期（如有）、查询日期，以及适用时间或条件。

价格分别说明是用户实付、官方公布还是平台展示价。一次收费或免票经历不扩展为通用政策；旧资料和缺少当前依据的班次、设施开放等内容注明适用范围。公开资料由 Agent 继续核实，用户主要补充真实经历与原始素材。

### 2.7 输出路线基础资料 MD

更新已有路线资料文件；尚无文件时，创建名称可识别的路线基础资料 MD。使用以下资料块，来源清单及索引放在缺项之前：

1. 路线总览：区域、起终点、方向、主要特点。
2. 路线基础数据：身份、时间、统计与必要的口径说明。
3. 分段经历：范围、地形、路面、景观与实际体验。
4. 重要节点概述：节点及其行程作用、位置确认状态；推定地点保留候选与依据。
5. 住宿、营地与补给。
6. 入口费用、索道与下撤安排。
7. 到达起点与离开终点的交通。
8. 资料来源及相关文件索引：原始轨迹、当前轨迹记录、已有说明和引用资料；使用可访问的文件或网页链接。
9. 待补充与待核实：统一放在最后。

采用稳定的字段名和章节，将内容、来源、适用范围和状态放在对应资料附近，便于后续直接提取。正文保留有效信息；未确定的内容不写成已确认事实。整理资料不直接改写轨迹或标注点源数据。

### 2.8 完成后的补充提醒与更新

保存后主动告知用户文件位置、已整理的范围及最影响后续使用的两到三项缺口。**分段经历需要单独提醒**：按现有分段说明还缺哪些实际耗时、体力感受、休息补给或具体经历；已经提供的路况和景观不重复索取。

未确认的地点单独提醒用户核对候选名称及实际含义，附上点位或分组编号和推定依据。文末将缺项分成「请用户补充」与「Agent 继续核实」。每项写清需要什么、关联哪一段或哪一个节点，以及补充后能完善什么。用户可按编号分次补充；收到新信息后写入对应正文，并移除或更新已经解决的缺项。

提醒示例：

> 基础资料已整理到文档。各段的路况与景观已有，请继续按分段补充实际耗时、体力感受和具体休息补给；返程班次由 Agent 继续核实。完整缺项在文末，可以分次回复。

完成第一步时，应能从文档读出路线怎么走、各段有什么特点、住宿补给与到达离开的基本安排，并看清来源及尚待补充的内容。

## 三、第二步：标注点整理（继续讨论）

### 3.1 整理依据

以当前轨迹的标注点编辑结果为依据，整理：

- 点位编号、名称、描述和类型。
- 真实坐标、海拔及时间。
- 关联图片及其来源。
- 当前分组关系和显隐状态。

地点名称与确认结果复用第 2.3 节；完整点位整理中新发现的位置疑问，继续按该流程反推并请用户确认，避免把待确认地名直接用于背景调查。

### 3.2 不同情况的处理

以下情况需要分别确定处理规则，目前先列出讨论方向：

| 情况 | 初步整理方向 | 仍需确定的内容 |
| --- | --- | --- |
| 独立点位 | 逐点整理 | 提取字段及内容完整度 |
| 分组点位 | 区分分组概述与成员细节，避免重复 | 分组和成员分别保留哪些信息 |
| 隐藏点位 | 识别当前显隐状态 | 是否纳入资料、是否标记为隐藏 |
| 有图片的点位 | 文字信息与图片信息可以分开整理 | 是否识图、提取哪些内容、如何核实 |
| 无图片的点位 | 依据现有文字与位置整理 | 是否需要补充外部资料 |
| 缺少名称或说明的点位 | 缺少地点名称时按第 2.3 节反推候选，其他说明列为待补充 | 可采用的资料字段及说明范围 |
| 地点含义未确认的点位 | 按第 2.3 节结合真实位置反推候选，并请用户确认 | 复用确认结果；无法确认时保留候选状态 |

### 3.3 点位与路线的关系

- 按经过顺序整理点位。
- 说明点位所在路段及其作用。
- 可按起终点、景观、路口、补给、休息、住宿等用途分类。
- 区分轨迹记录中已有的经过信息与后续调查得到的地点信息。

### 3.4 信息边界

- 真实地理位置与 SVG 画布中的排版位置分别处理。
- 资料整理不直接改写当前轨迹或标注点。
- 原有名称、描述、分组及图片引用保留；需要修正时先列出依据与建议。

## 四、第三步：背景信息调查（继续讨论）

### 4.1 路线背景

- 所在区域。
- 路线名称与常见叫法。
- 路线特点。
- 常见走法，以及与当前轨迹记录的对应关系。

### 4.2 环境背景

- 地形、植被和景观。
- 季节变化。
- 影响通行的天气、开放情况及其他条件。

### 4.3 标注点背景

- 标注地点名称的核对。
- 自然或人文背景。
- 地点的实际用途。
- 地点与当前路线的关系。

### 4.4 与第一步衔接

交通、入口、住宿补给、索道与返程等实用基础信息在第一步整理。第三步复用已有结果，按后续用途深入调查路线与地点的自然、人文、季节和环境背景，并补充第一步尚未核实的公开资料，避免重复整理。

### 4.5 来源与核实

- 区分轨迹数据、用户经历和外部资料。
- 外部资料记录来源、发布日期（如有）与查询日期；旧资料说明其适用范围。
- 对住宿、补给、索道票价与开放等可能变化的信息记录适用时间或条件；价格区分官方公布、平台展示和用户实付。
- 条件好坏、路段精华等体验判断标明来自用户，不由个别商家资料推定全线水平。
- 冲突、不确定及暂时缺少依据的内容单列，不直接写成确定结论。

## 五、统一输出结构

暂定将结果拆成以下资料块；是使用单个文档的分节，还是多个文件，后续再确定：

1. 路线基础资料与分段经历。
2. 点位资料。
3. 路线背景。
4. 点位背景。
5. 来源清单及必要的索引、附录。
6. 待补充与待核实事项（放在整理结果的最后）。

每条资料尽量关联轨迹编号或点位编号，并记录内容、来源和核实状态，方便后续准确提取。

### 整理完成后的提醒

- 「待补充与待核实」统一放在整理结果的最后，来源清单、点位索引及附录放在它之前。
- 区分需要用户补充的真实经历、说明和原始素材，以及需要 Agent 继续核实的数据冲突与外部资料；不要把全部调查工作交给用户。
- 缺项写清楚需要补充什么、关联哪条路线或哪个点位，以及补充后可完善的内容。
- 整理完成后，主动向用户提醒主要缺项，优先列出最影响后续提取的两到三项，并指向文档末尾的完整清单，不能只保存文档而不提醒。
- 分段经历须单独提醒：列出已有分段及仍缺的耗时、体感、休息补给或具体经历；已补充的路况与景观不重复要求。
- 提醒用户可以按编号回复或提供相关素材；暂时无法提供的内容继续保留为待补充或待核实。收到补充后，更新对应资料和缺项状态。

第一步按第 2.7 节交付基础资料；本节是完整 Skill 后续模块的输出方向。文末缺项及完成后提醒方式沿用第一步，其他模块继续完善。
